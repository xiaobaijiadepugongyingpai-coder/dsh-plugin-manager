# DSH 插件离线安装教程

> 适用环境：Windows + DSH Desktop 0.2.2-rc.1
> 原因：市场内安装会触发 pnpm 全量重排（约 347 个包），必须替换 `node_modules/electron`（被桌宠进程占用）和 `lightningcss`（被主进程加载，无法卸载），因此在 DSH 运行时**必然失败**。离线安装绕开了这个冲突。

---

## 一、工具位置

```
%USERPROFILE%\.dsh\tools\
├── 插件管理.cmd              ← 双击运行（v2 仪表盘 + 命令）
├── dsh-plugin-manager.ps1    ← 主程序
├── lib\
│   ├── catalog.ps1           ← 插件目录（下载/缓存/搜索）
│   └── build-index.js        ← 生成搜索索引
├── .cache\                   ← 目录缓存（自动生成，已被 git 忽略）
├── 安装插件.cmd              ← 旧版：只装单个插件
└── dsh-install-plugin.ps1    ← 旧版脚本
```

把 `插件管理.cmd` 右键发送到桌面，做成快捷方式最方便。

### 界面

启动后是一屏仪表盘，下面直接敲命令：

```
  DSH 插件管理器   2026-11-08 13:04
  ----------------------------------------------------------------------------
  #   插件                                         版本          状态
  1   @eddyskywalker/dsh-chatgpt-subscription    0.62.0      未启用
  2   dsh-better-sidebar                         0.30.1      启用
  3   dsh-pet                                    0.4.5       启用  → 0.4.6
  ----------------------------------------------------------------------------
  17 个插件 · 15 启用 · 2 未启用 · 12 个可更新（1 天前检查）

  > _
```

### 命令

| 命令 | 作用 | 需要退出 DSH |
|---|---|---|
| `i 关键词` | 从插件市场目录搜索并安装 | ✅ |
| `3` 或 `dsh-pet` | 查看插件详情 + 操作菜单（更新 / 卸载 / 打开仓库） | — |
| `u 3` 或 `u dsh-pet` | 更新指定插件 | ✅ |
| `u all` | 更新全部（`pnpm up --latest`） | ✅ |
| `rm 3,5` | 批量卸载 | ✅ |
| `refresh` | 刷新插件目录缓存（约 60 秒） | ❌ |
| `check` | 立即检查更新（启动时已自动检查，通常不需要） | ❌ |
| `ls` | 重绘仪表盘 | ❌ |
| `help` / `q` | 帮助 / 退出 | — |

> 表中尖括号 `<...>` 表示占位，**实际输入时不要写**。例如搜插件直接输 `i sidebar`，不是 `i <sidebar>`。


> `check`、`info`、`ls`、`refresh` 都只读，随时可以跑。
> 仪表盘上的 `→ 0.4.6` 是缓存的上次检查结果，想看最新的就跑一次 `check`。

## 三、方式一：用管理器安装（推荐）

### 步骤

1. **完全退出 DSH**
   托盘图标右键 → 退出。然后打开任务管理器，确认 **DeepSeek Harness 进程为 0**。
   （脚本会自己检查，没退干净会直接拒绝执行）

2. **双击 `插件管理.cmd`**

3. 输入 `i 关键词` 搜索，或直接输包名：

   ```
   > i computer-use
   ```

4. 选序号 → 输入 `y` 确认 → 等待安装完成（10–60 秒）。

5. **启动 DSH**，插件即生效。

> 脚本会自动：备份配置 → `pnpm add --save-exact` → 写入 `bundles` → 检查并修复 electron 二进制。

### 脚本做了什么

| 步骤 | 说明 |
|---|---|
| 1 | 检查 DSH 是否已退出 |
| 2 | 备份 `package.json`、`pnpm-lock.yaml`、`cordis.patch.yml` 到 `_install-backup-时间戳\` |
| 3 | 在 profile 目录执行 `pnpm add <包名>` |
| 4 | 把包名写进 `package.json` 的 `dsh.profile.bundles`（插在 `@linxin666/dsh-web-all` 之前） |
| 5 | 检查 `node_modules\electron\dist\electron.exe` 是否还在，缺失则用国内镜像自动修复 |

## 四、方式二：手动三步

不想用脚本时，手动操作等价于：

### 1. 退出 DSH，打开 PowerShell

```powershell
cd $env:USERPROFILE\.dsh\profiles\desktop
pnpm add dsh-computer-use-win
```

> 装指定版本：`pnpm add dsh-computer-use-win@0.5.4`
> 作用域包：`pnpm add @xmanrui/dsh-im@5.10.0`

### 2. 把包名加进 `package.json` 的 bundles

用记事本打开 `%USERPROFILE%\.dsh\profiles\desktop\package.json`，在 `bundles` 数组里加一行：

```json
"dsh.profile.bundles": [
  "@deepseek-ai/dsh-base",
  "@deepseek-ai/dsh-web-app",
  ...
  "dsh-computer-use-win",        ← 加在这里（放在 @linxin666/dsh-web-all 之前）
  "@linxin666/dsh-web-all"
]
```

> ⚠️ 只加进 `dependencies` 不够，**必须加进 `bundles` 才会被加载**。

### 3. 启动 DSH

## 五、卸载插件

**方式一：用管理器**

双击 `插件管理.cmd` → `[5] 卸载插件` → 按列表输入序号 → 输入 `y` 确认。

脚本会自动完成：`pnpm remove` + 从 `bundles` 移除 + 检查 electron 二进制。

**卸载后会额外询问：是否同时删除该插件的配置和存档？**

### 删除配置/存档的影响

| | 保留数据（默认） | 删除数据 |
|---|---|---|
| 插件代码 | 删除 | 删除 |
| 插件设置 | ✅ 保留，重装后自动恢复 | ❌ 丢失，重装回到初始状态 |
| 账号/登录态 | ✅ 保留 | ❌ 需重新登录 |
| 插件自己的历史（如桌宠的亲密度、喂食记录） | ✅ 保留 | ❌ 丢失 |
| 占用空间 | 继续占用 | 释放 |

**会删除什么**（只在这两个位置找）：

- `~/.dsh/<插件名>`，例如 `dsh-pet` → `~/.dsh/dsh-pet`
- 少量已知映射，例如 `dsh-pet` 还会匹配 `~/.dsh/pet.json` 和 `~/.dsh/pets`

**绝不会碰**：`profiles`、`storages`、`skills`、`logs`、`dsh-session-archive` 等核心目录。你的会话记录、聊天历史、技能、profile 配置都在这些目录里，脚本有硬编码的保护名单，即使插件名撞上也不会删。

### 三道安全措施

1. **默认保留**——直接回车就是不删；
2. **二次确认**——输入 `y` 之后，还要手动输入**完整包名**才执行，输错就放弃；
3. **只移动不删除**——数据被移动到 `~/.dsh/_uninstall-trash-时间戳\`，随时可以取回：

```powershell
# 想恢复
Move-Item "~\.dsh\_uninstall-trash-20261106-190000\dsh-pet" "~\.dsh\dsh-pet"

# 确认不要了，再手动删除
Remove-Item "~\.dsh\_uninstall-trash-20261106-190000" -Recurse
```

> 已知局限：`dshmarket` 的数据在 `profiles\desktop\.dsh-market` 下，因为位于 profile 内部，脚本**故意不处理**——宁可少删，也不冒险碰 profile。

**方式二：手动**

```powershell
# 1. 退出 DSH
cd $env:USERPROFILE\.dsh\profiles\desktop
pnpm remove 包名
```

然后从 `package.json` 的 `bundles` 数组里删掉对应那一行。

## 七、electron 二进制被清空时

pnpm 替换 `node_modules/electron` 后会清掉里面的 357 MB 二进制（store 里没有），导致 DSH 启动时卡在下载 GitHub。修复命令：

```powershell
cd $env:USERPROFILE\.dsh\profiles\desktop\node_modules\electron
$env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_CUSTOM_DIR = "{{ version }}"
node install.js
```

约 19 秒完成。**脚本会自动检查并修复这一步**，手动操作时才需要自己跑。

判断标准：`node_modules\electron\dist\electron.exe` 是否存在。

## 八、常见错误对照表

| 报错 | 原因 | 处理 |
|---|---|---|
| `EPERM: rename '...electron_tmp_xxx' -> '...electron'` | 桌宠进程占着 electron | 把 `~/.dsh/dsh-pet/main-config.jsonc` 的 `display` 改成 `"web"`，重启 DSH |
| `EPERM ... lightningcss-win32-x64-msvc` | DSH 主进程加载了该原生模块 | 只能离线装（本教程的做法） |
| `ERR_PNPM_EPERM` 出现在 `package.json` / `pnpm-lock.yaml` | 杀毒软件或索引服务正在读文件 | 再执行一次即可，通常第二次就成功 |
| `ERR_PNPM_OUTDATED_LOCKFILE` | `package.json` 和 `pnpm-lock.yaml` 不一致 | 先跑 `pnpm install --lockfile-only` 同步 |
| 装完 DSH 起不来 | 树被改乱 | 从 `_install-backup-时间戳\` 还原三个文件 |
| 启动报 `Web authentication failed` | Electron 会话数据损坏 | 重命名 `%APPDATA%\@deepseek-ai\dsh-desktop` 后重启 |

## 九、注意事项

1. **一次只装一个**，别连着点。失败后先看日志再重试——每次失败都会往 `node_modules` 里留残骸，越试越乱。
2. **装之前一定确认 DSH 进程为 0**。少退一个进程，`electron` 就会被占用。
3. **备份不要删**。`_install-backup-*` 目录是出问题时的救命稻草，确认稳定后再清理。
4. **不要用市场更新已加载的插件**。更新比安装更容易撞锁，一律走离线。
5. **装完别急着删安装包缓存**，出问题时可能需要重装应用。

## 十一、同名插件怎么区分

### 唯一标识是「完整包名」，不是显示名

npm 的包名全球唯一，**带 `@` 的作用域部分也是名字的一部分**。所以：

| 显示名 | 完整包名 | 是不是同一个 |
|---|---|---|
| 桌宠 | `dsh-pet` | ❌ 不同 |
| 桌宠 | `@linxin666/dsh-pet` | ❌ 不同（这是 `@linxin666/dsh-web-all` 的传递依赖） |

你机器上实际就同时存在这两个包（共 376 个包里，末段同名的有 30 多组）。它们**不会互相覆盖**，因为目录不同：`node_modules/dsh-pet` 和 `node_modules/@linxin666/dsh-pet`。

### 脚本里怎么输入

直接输入**完整包名**，包含 `@` 作用域：

```powershell
# 对
@linxin666/dsh-pet
@xmanrui/dsh-im
dsh-computer-use-win

# 错（会装成另一个包，或直接报 404）
dsh-pet          ← 如果你想要的是 @linxin666/dsh-pet
```

`bundles` 里同理，必须写完整包名，写简称不会被识别。

### 三种「同名」情形

| 情形 | 例子 | 怎么处理 |
|---|---|---|
| **同末段、不同作用域** | `dsh-pet` vs `@linxin666/dsh-pet` | 用完整包名区分，互不影响 |
| **同包名、不同来源** | `dsh-pet`（npm）vs `dsh-pet`（GitHub） | 用 spec 指定来源（见下表） |
| **同功能、不同包** | 两个作者各写了一个桌宠 | 只留一个，同时装可能冲突 |

### 指定来源的写法

```powershell
pnpm add 包名@版本                        # npm 指定版本
pnpm add 包名@latest                      # npm 最新
pnpm add 包名@github:用户名/仓库名         # 从 GitHub 装
pnpm add 包名@https://.../xxx.tgz         # 从 tarball 装
pnpm add 包名@file:../本地路径             # 从本地目录装
```

### 装之前先确认是哪一个

```powershell
npm view dsh-pet name version repository.url
npm view @linxin666/dsh-pet name version repository.url
```

对比 `repository.url` 就知道哪个是你要的。

装完之后也可以验证：

```powershell
Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\你要查的包名\package.json" |
  ConvertFrom-Json | Select-Object name, version, repository
```

### 传递依赖不算「已装」

只有写进 `package.json` 的 `dsh.profile.bundles` 的包才会被加载。

`@linxin666/dsh-pet` 虽然躺在 `node_modules` 里，但它只是 `dsh-web-all` 的依赖，**没有进 bundles，所以不会作为独立插件运行**。你在市场「已安装」里看到的只有 `dsh-pet`。
